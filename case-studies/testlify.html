The Challenge

Hiring software is high-stakes. Bad design leads to wrong hires, biased evaluation, legal exposure, and client churn.

When I joined, Testlify had powerful features but dangerous complexity: AI vs manual scoring, configurable proctoring, and white-label environments.

Every configuration decision cascaded. One employer toggle affects:

  • Candidate statuses
  • Report structures & PDF logic
  • Historical data mapping
  • Cross-platform rendering
The design question: How do we preserve flexibility without introducing confusion, risk, or unintended consequences?

My answer: Build guardrails, not gates. Make complexity transparent. Give users control, but prevent catastrophic errors.

5 Core Design Principles

1. Control Over Automation
AI assists, not replaces. Provide manual overrides, pause capabilities, and transparency.
2. Transparency in Complexity
Make complexity visible and understandable. Show sync states, threshold logic, criteria scoring.
3. Guardrails, Not Gates
Enable power users while protecting novices. Use confirmations, limits, warnings — don't block.

Deep Dive: AI Resume Parser

The Ask: Client requested automated resume screening via ATS. Founder wanted it as a scalable feature for all customers.

The Risk: Over-automation could silently reject qualified candidates — causing hiring mistakes, legal liability, and client churn.

Design Exploration

Option A: Fully Automatic

Upload resume → AI scores → Auto-reject

Pro: Fast, scalable

Con: No employer visibility, irreversible errors, trust erosion

Option B: Manual Review Required

AI scores → Employer reviews each → Manual decision

Pro: Complete control, no automation errors

Con: Defeats automation purpose

Option C (Selected)

CHOSEN

AI suggests criteria → Thresholds setup → Transparent scoring → Manual overrides

Pro: Reduces workload while preserving control.

The Flow I Designed

1. ATS Integration & Job Mapping

Enforced Greenhouse connection before access. Designed empty states for every failure mode (ATS not connected, No jobs exist, etc.) to prevent broken flow entry. Employers map the tool to specific stages.

🔌 ATS Gate

2. AI Criteria Suggestion

AI suggests 10 criteria based on role + JD. Employer must actively select a minimum of 8 using selectable chips. This forces human judgment instead of blind reliance on generation.

✨ Criteria Generation

3. Threshold Configuration

Designed slider snap-points categorized into High/Medium/Low bands with strict color coding (green/amber/red). Ex: "Below Low Band → Auto-Reject". This prevents granular numbering errors from employers.

🎛️ Threshold Sliders

4. Safety Controls & Overrides

  • Mandatory Confirmation: Explicit pop-ups block irreversible auto-rejections.
  • Global Sync Caps: Default limit of 20 candidates/batch shields from volume errors.
  • Exposed Sync States: Highly visible "failed/syncing" states to be honest about ATS dependencies.
🛡️ Safety Overrides

Deep Dive: Reporting as a Product

The Problem: Reports were treated as messy raw data exports instead of client-facing products used in board presentations and HR reviews.

Architectural Approach
Implementation Details
Core Report Redesign
Introduced clear readable typographies. Replaced data walls with accordion patterns, donut charts, and an at-a-glance interpretation section.
8 Psychometric Frameworks
Created a bespoke, modular block system supporting 8 varying tests (Big Five, Enneagram, Sales Profiler etc.). Ex: Used horizontal bar charts for Big Five instead of complex radar charts for immediate print readability.
Export Tiers
Built granular extraction menus: Single assessment, Library-only, or Merged bundles. Serving Hiring Managers vs HR Leaders.

Decision Visibility in Libraries
