2. THE REAL PROBLEM

Hiring software operates in a high-stakes environment. Design mistakes can lead to:

  • Wrong hires (financial loss, productivity impact, team morale decline)
  • Biased evaluation (legal exposure, reputation damage)
  • Client churn (revenue loss)
  • Operational chaos (fragmented workflows, inconsistent scoring)

When I joined Testlify, the platform had strong functional depth but growing complexity:

AI vs. manual scoring options

Configurable proctoring rules with tolerance thresholds

Multiple question types (MCQ, hands-on, third-party integrations, voice/video AI)

ATS integrations (Greenhouse)

Psychometric reports (Big Five, 16 Personality, Enneagram, and more)

White-label environments

Reseller-managed workspaces

Multi-language support

The challenge wasn't adding more features. It was preventing the system from collapsing under its own complexity. Every configuration decision cascaded across multiple surfaces:

One employer toggle could affect:

  • Candidate status
  • Report output structure
  • PDF generation logic
  • Shareable link visibility
  • Historical data consistency
  • Cross-platform behavior
The core design question became:

How do we preserve flexibility without introducing confusion, risk, or unintended consequences?

4. DESIGN PRINCIPLES

Five core principles guided my decisions across 18 months:

1. Control Over Automation
AI and automation should assist decisions, not replace them. Always provide manual override options, pause capabilities, and clear transparency into what the system is doing.
2. Transparency in Complexity
When systems are complex, make complexity visible and understandable—not hidden. Show sync states, threshold logic, criteria scoring, and configuration impact.
3. Progressive Disclosure
Don't overwhelm users with all options at once. Reveal configuration depth step-by-step based on user journey and technical comfort level.
4. Guardrails, Not Gates
Enable power users while protecting novice users. Use confirmation modals, default limits, and clear warnings—but don't block capabilities.
5. Consistency Across Chaos
As features expanded rapidly, maintain consistent patterns: status indicators, action buttons, empty states, error handling, sync visibility.

5. Major Contribution: AI Resume Parser

The Ask

A client requested automated resume screening integrated with their ATS workflow. The founder wanted it built as a scalable feature for all Testlify customers, not a one-off solution.

The Risk

Over-automation could silently reject qualified candidates. Incorrect threshold configuration, unclear criteria selection, or aggressive automation without transparency could:

  • Cause hiring mistakes
  • Damage client trust
  • Create legal liability
  • Generate support tickets
  • Hurt sales demos

What I Designed

I structured the complete AI Resume Parser flow, integrating with Greenhouse ATS:

1. ATS Integration Gate

Employers must integrate Greenhouse ATS via Settings before accessing Resume Parser. Designed contextual empty states for different system conditions (ATS not connected, no jobs exist, no candidates available, job not configured).

Why: Prevent users from entering a broken flow. Make prerequisites clear upfront.

2. Job Selection & Stage Mapping

System displays ATS jobs in "Not Setup" state by default. Employer selects which ATS stage to fetch candidates from and optional job description upload.

Why: Connect external pipeline data with internal screening logic. Allow flexibility in when candidates enter screening.

3. AI Criteria Suggestion

Based on role name and job description, AI suggests 10 evaluation criteria. Employer must select minimum 8 criteria. Option to create completely custom criteria from scratch.

Why: Balance AI assistance with recruiter judgment. Prevent over-reliance on AI while reducing manual work.

4. Score Threshold Configuration

Employer defines three threshold bands: High / Medium / Low. Configures automation rules for each band (Above X score → Automatically move to next ATS stage; Below Y score → Automatically reject).

Why: Make automation consequences explicit. Force deliberate decision-making about rejection thresholds.

5. Parsing Controls

Default candidate processing limit: 20 per batch. Pause/resume capability during active screening. Sync status visibility. Manual re-sync option as fallback.

Why: Prevent bulk processing errors. Allow recovery from mistakes. Handle ATS dependency failures gracefully.

6. Candidate Evaluation Interface

Under each job, employers see High/Medium/Low badges and criteria-level scoring breakdown. On candidate detail page: resume preview, basic info, manual action controls (Reject, Move stage, Invite).

Why: Provide transparency into AI decisions. Maintain human control at all decision points.

Key Design Decisions

1. Mandatory Confirmation Before Rejection

Added explicit confirmation popup before automated rejection activates.

Why: Rejection is irreversible and affects careers. Trade-off: Adds friction, but prevents accidental bulk rejection.

2. Pause Capability

Allowed employers to pause screening mid-process.

Why: If they notice incorrect threshold settings after starting, they need immediate stop capability. Trade-off: Added UI complexity, but critical safety feature.

3. Sync Transparency

Made ATS sync status highly visible with manual fallback option.

Why: External ATS dependency creates unpredictable failure states. Trade-off: Exposes technical complexity, but builds trust.

4. Default Candidate Limit

Set default processing cap at 20 candidates per batch.

Why: Prevent overwhelming first-time users. Reduce bulk processing errors. Trade-off: Power users need to manually increase, but safer default.

The Trade-Off I Made: Speed vs. Safety

I could have designed fully automated screening—upload resume, get instant decision, zero human involvement. Instead, I chose controlled automation: Explicit threshold configuration, confirmation before rejection, manual override at every stage, transparent sync states, pause capability.

Why this matters: Fast automation feels impressive in demos. But responsible automation builds long-term client trust. I optimized for reliability over speed.

Impact

Transformed Testlify from passive assessment tool → active AI screening layer embedded in existing hiring pipelines. Enabled ATS-based candidate filtering before manual review, configurable automation, scalable screening without sacrificing employer control, and a foundation for expanding beyond Greenhouse.

6. Other Key Contributions

Decision Visibility Across Libraries

The Problem: Employers had access to 3,000+ tests, 182,000+ questions, 100+ templates, and 100+ interview kits. No quick way to assess which assets were actually proven or popular.

What I Did: Added "Candidates Assessed" count directly on listing cards and detail pages across all library types.

Why This Mattered: Small UI addition. Large behavioral impact. Instead of guessing, employers could see usage patterns and make confident asset selections. This type of micro-improvement—repeated across 500+ tickets—is what kept the system coherent as it scaled.

Reporting as a Product

The Problem: Reports were treated as exports. But they're consumed by HR teams, leadership, candidates—shared externally. Poor reports damage product perception.

What I Did: 1. Redesigned Core Reports (Assessment-level, Test-level, Visual hierarchy improvements, Score presentation logic refinement, Data readability enhancements). 2. Designed 8 Psychometric PDF Reports (Big Five, 16 Personality, Enneagram, Leadership Style, Sales Profiler, Leadership Potential, 360 Degree Feedback, PicOcean). 3. Improved Export Structure (Single assessment report, Library-only report, Merged PDF, ZIP download).

Design Goal: Make complex psychometric data readable and credible for non-technical HR users. Turn data dumps into professional insights.

Employer Portal Structural Improvements

As features expanded, certain areas became fragmented. I restructured:

  • Navigation Information Density: Added count indicators showing platform scale (Tests: 3,000+, Questions: 182,000+, Templates: 100+, Interviews: 100+). *Why: Reinforce product value, increase perceived depth, improve decision confidence.*
  • Referral System: Designed "Refer & Earn $500" feature + landing page, creating organic growth channel and retention loop.

Goal: Reduce cognitive load. Make complex enterprise operations understandable.

Marketing Website Contributions

  • AI Capability Positioning: Made AI assistance vs. automation distinction clear, avoided "AI will do everything" messaging, showed human control remained central, aligned claims with actual product behavior. *Why: Overstated AI creates unrealistic expectations. Had to balance "cutting-edge" positioning with honest capability representation.*
  • Feature Communication Structure: Improved information hierarchy for complex features (Assessment creation, proctoring, ATS integrations, psychometrics, white-label).

Impact: Improved clarity for enterprise prospects, reduced sales friction from misaligned expectations, and strengthened credibility through honest capability representation.

7. Cross-Platform Considerations

Testlify operates across multiple environments, requiring constant validation:

  • Platforms: Employer Portal (Desktop web), Candidate Experience (Web + Android/iOS apps), Browsers (Chrome, Safari, Edge, Firefox), OS (Windows, macOS, iOS, Android).
  • My Validation Process: Validated desktop responsiveness, tablet layouts, mobile web compatibility, Android/iOS native app parity, browser rendering differences, and OS-level inconsistencies.
Why This Mattered

Employer-side decisions directly affected candidate-side experience. For example, an employer enabling a video question affects mobile camera permissions, browser permission handling, performance on older devices, and instruction clarity. Design decisions weren't screen-based; they were behavior-based across touchpoints.

8. THE MESSY REALITY (WHAT MADE THIS HARD)

This wasn't clean product work. It was structured chaos. Here's what made it challenging:

1. No Structured UX Validation Layer

My reporting manager came from a graphic design background. There was no senior UX reviewer or structured design critique process.

My solution: Used AI tools to stress-test logic, simulate edge cases, and identify potential interaction loops.

2. Revenue-Driven Prioritization

Client requests (when revenue-linked) took priority over long-term UX refinement or technical debt.

My approach: Documented design debt. Flagged risks clearly. Balanced urgency with minimum viable quality.

3. Cross-Browser/OS Inconsistencies

Web-first platform used across Chrome, Safari, Edge, Firefox, plus different operating systems. What works in Chrome/Windows might break in Safari/macOS.

My process: Validated every feature across environments.

4. Constant Context Switching

Simultaneously worked on Employer portal workflows, Candidate experience flows, Marketing website pages, PDF report structures, Configuration settings, White-label environments.

Impact: Required strong mental models of how different surfaces connected.

5. Supporting Junior Designers While Shipping

The team included designers with under 2 years experience who needed complex flow reviews, ticket structuring help, and logic validation.

My contribution: Reviewed their work before dev handoff. Helped maintain quality bar.
